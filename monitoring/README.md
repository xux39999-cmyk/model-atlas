# 官方来源监测

程序读取 `dist/models-data.js` 中的官方来源，合并重复网址，每天检查一次网页文本是否变化。不调用 AI 模型、不需要第三方 API Key、不自动改免费政策，也不改资料核查日期。

## 启用

1. 将本次代码通过 GitHub Desktop 推送到 GitHub 的 `main` 分支。
2. 在仓库 Settings → Actions → General 中，确认允许运行这些 Actions，并勾选允许 GitHub Actions 创建 Pull Request 的选项。不要添加个人 Token，也不需要授权所有仓库。
3. 在 Actions 中选择 `Check official model sources` → `Run workflow`，先手动运行一次。
4. 打开运行结果的摘要查看检查报告。首次运行会创建一个草稿 Pull Request，等待审核网页对照基线。
5. 审核并合并首次基线后，后续每天北京时间约 10:17 检查；由 GitHub 云端执行，电脑可以关机。GitHub 调度可能延迟，不保证准点。私有仓库运行会使用账号的 Actions 配额，具体限制以 GitHub 账单为准。

如果仓库不允许机器人创建 PR，检查报告仍可在该次 Actions 摘要及 artifact 中查看，但创建 PR 的步骤会失败。需要先修正设置，流程才算完整启用。

## 什么会提醒

- 首次看到一个来源：建立对照，不能判断此前政策是否改变。
- 已有来源的网页文本变化：创建或更新同一个草稿审核 PR。
- 首次发生或类型变化的检查错误、访问恢复、来源删除：生成审核报告。
- 无变化：不新建审核申请；每次运行摘要仍保留结果。

网页中导航、页脚、日期等变化也可能触发报告；纯动态网页、反机器人页面、错误页和区域差异可能造成误报或漏报。指纹仅代表程序读取到的文本，不代表政策已重新核查。程序没有新增模型的全网发现功能，范围仅限目录中已列出的网址。

## 人如何审核

打开报告列出的官网，判断是否涉及模型、额度、期限、地区或商用条件。需要修改时另改 `dist/models-data.js`，重新核实后更新对应 `checkedAt`。合并监测 PR 只接受网页指纹，不代表政策已核实，不直接改网页资料。

`baseline.json` 保存上次接受的网页指纹及访问状态，不保存完整网页。访问失败保留旧指纹，不覆盖为错误页。未合并的变化会持续与旧基线比较，并更新同一个审核分支，不会每天新建一个 PR。

## 本地运行

有 Node.js 20 或更新版本时：`node scripts/monitor-sources.cjs`。该命令会联网并写入报告与候选基线；不要未经核查就把候选基线当成政策结论。
